# OpenCode 适配

仅在当前宿主是 OpenCode 且相关能力可用时采用这些策略；核心课程流程和授权边界不变。

## 提问

- 新开课程或切换方向时优先使用 `question` 工具承载针对式提问。
- 每次调用优先放入 1–3 个彼此相关、能直接改变课程起点的问题，避免逐题制造往返。
- 每题提供 2–4 个根据上下文生成的具体选项；推荐项排第一并按工具约定标注
  `（Recommended）`，由工具保留自由回答入口，不另加“其他”选项。
- 不把单纯的下一单元选择误判为切换方向。只有主题、目标、路线或关键约束发生变化时，
  才重新执行方向诊断。
- 若 `question` 不可用，使用同样内容的简短文本提问，不中断流程。

## 资料核实

- 涉及库、框架、SDK、API、CLI 或云服务的当前用法时，优先使用 Context7 获取当前文档。
- 涉及当前项目行为时，先用 `glob`、`grep` 和 `read` 检查代码、配置及测试，不凭通用知识推断。
- 只有 Context7 不适用的时效信息才使用网页资料；优先一手来源，并记录版本或核实日期。
- 稳定基础知识和纯练习设计不调用外部资料工具。

## 计划与执行

- 课程计划需要三步以上操作时可用 `todowrite` 跟踪当前执行工作，但它不能代替
  `COURSE_PLAN.md` 的跨会话学习记录。
- 读取使用 `read`；查找使用 `glob`/`grep`；手工修改计划使用 `apply_patch`。
- 写入前再次 `read` 目标计划，保留学习者或其他 agent 的并发修改。
- 可并行且互不依赖的资料读取使用并行工具调用；提问、选择、教学和验证必须保持顺序。
- 不为完成课程流程调用子 agent；只有主题研究本身复杂且能与当前交互解耦时才委派研究。

## 环境探测

- 先用 `question` 告知拟检查的环境项和保存范围；用户允许后才运行探测。一次授权只覆盖已说明的
  只读项目，不自动扩展到其他配置、目录或凭据。
- 使用 `bash` 运行课程相关工具的标准只读版本命令，例如 `<tool> --version`；单独执行必要命令，
  不使用会安装、升级、登录、联网修改状态或输出全部环境变量的命令。
- 系统信息只取教学所需的最小集合，例如内核/操作系统、架构和当前 Shell。项目配置优先用
  `read` 查看明确相关的清单文件，禁止为建档读取 `.env`、凭据目录、密钥文件或认证数据库。
- 使用 `command -v <tool>` 判断命令是否存在时，只保存存在状态或必要的可执行文件路径；
  若路径包含用户名等无关个人信息，计划中省略或概括该路径。
- 可相互独立的版本检查使用并行工具调用。探测失败不自动尝试安装或修复，先记录结果，
  再把安装或修复作为可选教学方向交给学习者。
- 保存前展示将写入环境快照的信息摘要；学习者要求排除的字段不得落盘。
